# Workstation bootstrap

One command to set up an OnePeek workstation (macOS or Linux), for example a new laptop. It does `onepeek-docs` `standards/start-here.md` §2 for you. You need to be a member of the GitHub organisation first. Run it in a terminal, because GitHub sign-in is interactive.

This repo is public, so cloning it needs no sign-in:

```bash
mkdir ~/OnePeek && cd ~/OnePeek
git clone https://github.com/OnePeek/.github.git
.github/workspace/bootstrap.sh
```

The repos are cloned beside `.github`. Options:

```bash
bootstrap.sh                  # everything, local stack in --mode minimal
bootstrap.sh --mode default   # adds ClamAV and observability
bootstrap.sh --skip-stack     # tools, clones and dependencies only
bootstrap.sh --check          # checks only, including `app doctor`
```

It is safe to re-run. In order, it:
1. Checks whether this account can write to Homebrew. If it can, tools come from Homebrew. If not (no Homebrew, or Homebrew owned by another account on the same Mac), they install per-user through mise, with no admin rights.
2. Signs in to GitHub with the `read:packages` scope, for the private `@onepeek/*` packages.
3. Clones every live `OnePeek/*` repo. Repos already there are fetched, and fast-forwarded only when they are clean and on their default branch.
4. Pins Node, Terraform, uv and tflint globally through mise, and enables pnpm through corepack.
5. Installs each repo's dependencies, then runs `setup.py` for the shared skills, agents and git hooks. That script never overwrites your own `CLAUDE.md`.
6. Installs and starts Docker Desktop, then runs `uv run app setup`, which ends with `app doctor`.

The data stores (Postgres, Mongo, Valkey, MinIO and the rest) are not installed on the laptop. They run as Docker containers defined in `backend-service/compose/` (see `onepeek-docs` `architecture/lld/infra/local-stack.md`).

Start developing: `cd backend-service && uv run app dev`, then open http://localhost:20080 (use `localhost`, not `127.0.0.1`).

## What needs an admin
Only Docker Desktop. On an account without admin rights the script prints the exact commands for an admin to run once, finishes everything else, and reports the local stack as not started. Re-run it after Docker is installed.

## Not in git: copy from the old machine
- your personal root `CLAUDE.md`, if you keep one
- the `[profile ...]` blocks of `~/.aws/config`, including `onepeek-local` (SSO)
- any `.env.local` files (`.env.secrets` is regenerated by `app secrets pull`)

## Keeping this current
The script lists no repos and no versions, so there is nothing to update when they change:

| What | Where it comes from |
|---|---|
| Repos | `gh repo list OnePeek --no-archived`. A new repo is picked up, and an archived one is dropped. |
| Node | `onepeek-web/.node-version` |
| Terraform | `onepeek-infra/.terraform-version` |
| uv, tflint | `UV_VERSION` and `TFLINT_VERSION` in `workspace/local_ci.py`, the versions CI uses |
| Python | each repo's `.python-version` (uv reads it) |
| pnpm | each repo's `packageManager` field (corepack reads it) |
| What to install in a repo | whether it has `pyproject.toml` or `package.json` |
